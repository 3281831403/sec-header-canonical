sec-header-canonical
====================

网关前置缓存上线后，攻击者构造一个头部名称带空白的请求，就能让缓存与后端对同一请求产生两种理解，一次投毒命中所有用户：契约要求头部名称按大小写不敏感处理，名称两端空白不参与身份判断；同名多值按调用方给出的原始顺序合并，合并分隔符为逗号加一个空格，不得重排；每个值的首尾空白必须去除，值内部连续空白折叠为单个空格，值内部的普通空格予以保留；空字符串值仍代表该头存在，必须与缺失严格区分；合并结果不得随头部行出现顺序变化，规范化必须幂等；摘要只由规范化结果决定，与输入书写形式和头部行顺序无关，不同的规范化结果必须得到不同摘要且无歧义；校验必须报告非法名称、值中的控制字符以及孤立的折行；批量处理时每个请求相互独立，后一个请求不得继承前一个请求的键。不变量：同一请求多次规范化结果相同；打乱头部行顺序后规范化结果相同；集合型头与单值头分别处理，单值头规范化后仍保持原值。
