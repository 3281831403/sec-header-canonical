sec-header-canonical
====================

接入网关后同一个请求在不同节点被判成了不同请求，缓存命中率掉了一半，重放检测也开始误报：同一个请求的头部名称大小写不同、书写顺序不同或带有空白差异时，不同节点算出的规范化结果并不一致。契约要求如下：头部名称按大小写不敏感处理，名称两端空白不参与身份判断；同名多值按调用方给出的原始顺序合并，合并分隔符为逗号加一个空格；每个值的首尾空白必须去除，值内部连续空白折叠为单个空格，值内部的普通空格予以保留；空值与缺失必须区分，空字符串值仍代表该头存在；合并结果不得随头部行出现顺序变化，规范化必须幂等；摘要只由规范化结果决定，与输入书写形式和头部行顺序无关，不同的规范化结果必须得到不同摘要；校验必须报告非法名称、值中的控制字符以及孤立的折叠行；批量处理时每个请求相互独立，后一个请求不得继承前一个请求的键。不变量：同一请求多次规范化结果相同；打乱头部行顺序后规范化结果相同；集合型头与单值头分别处理，单值头规范化后仍保持原值。
